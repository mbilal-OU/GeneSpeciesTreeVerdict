# Benchmarking and scientific validation

GeneSpeciesTreeVerdict v0.3 introduces a reproducible benchmark layer for testing whether its workflow decisions behave sensibly when the underlying truth is known.

## Why benchmarking matters

The framework integrates several familiar measurements—copy number, taxon coverage, topology discordance and duplication/loss reconciliation—but its scientific value depends on whether the **combined decision logic** behaves safely.

The benchmark therefore asks questions such as:

- Does a clean single-copy concordant locus remain `PASS`?
- Does explicit sampled multicopy duplication trigger `RESOLVE`?
- Does single-copy topology discordance avoid being converted into an unjustified `RESOLVE` decision?
- Does low coverage trigger `REVIEW` rather than a biological diagnosis?
- How often do controlled pseudo-orthology-like structures expose limitations of the current evidence layer?

## Native structural benchmark

The built-in generator uses seeded random binary species trees and controlled transformations of the corresponding gene trees. It provides exact truth for:

- sampled copy number;
- presence/absence of an explicitly introduced duplication;
- taxon coverage;
- whether topology was deliberately perturbed;
- whether only branch lengths were changed.

This is useful for validating program behavior and regression-testing the decision engine.

It is **not** a complete evolutionary simulator.

A topology perturbation can be used to stress-test the same decision path that real ILS, HGT, recombination or gene-tree error might activate, but the native benchmark does not claim to reproduce those processes mechanistically.

## Process-realistic validation

For process-level validation, use `--truth-manifest` with data generated by a specialist simulator.

### SimPhy

SimPhy implements a hierarchical species-tree/locus-tree/gene-tree model and can jointly simulate incomplete lineage sorting, gene duplication/loss, horizontal gene transfer and gene conversion. This makes it a strong target for testing whether GSTV remains conservative when different evolutionary processes generate similar observed discordance.

Reference: Mallo D, de Oliveira Martins L, Posada D. 2016. *SimPhy: Phylogenomic Simulation of Gene, Locus, and Species Trees*. Systematic Biology 65:334–344.

### Zombi

Zombi can simulate species trees, genome evolution and sequences, including duplications, losses and transfers. It is particularly useful for microbial-style genome evolution where gene content and transfer histories matter.

Reference: Davín AA et al. 2020. *Zombi: a phylogenetic simulator of trees, genomes and sequences that accounts for dead lineages*. Bioinformatics 36:1286–1288.

### Why external simulation is kept separate

GeneSpeciesTreeVerdict should evaluate evidence; it should not quietly embed a simplified simulator and then use that same simulator as proof that the method works. Keeping process simulation external reduces circular validation and makes it possible to benchmark the framework against independent generative models.

## Running the native benchmark

```bash
gstv benchmark --config benchmarks/smoke.yaml --outdir benchmark_results/smoke
```

A larger grid is provided as:

```bash
gstv benchmark --config benchmarks/full.yaml --outdir benchmark_results/full
```

## External truth-manifest mode

```bash
gstv benchmark \
  --truth-manifest external_simulation/truth_manifest.tsv \
  --outdir benchmark_results/simphy
```

Required TSV columns:

```text
benchmark_id
scenario
species_tree
gene_tree
expected_statuses
truth_has_duplication
truth_single_copy
```

Optional columns:

```text
truth_class
replicate
seed
taxa
mapping
delimiter
species_field
```

Tree and mapping paths are resolved relative to the manifest file.

`expected_statuses` can contain more than one acceptable workflow state separated by `|` when biological truth does not imply a uniquely correct software action.

## Metrics

The benchmark reports conventional per-state precision, recall and F1, plus project-specific safety metrics.

### RESOLVE sensitivity for sampled multicopy truth

Among scenarios where an explicit duplication leaves more than one sampled copy in a species, how often does GSTV return `RESOLVE`?

### False-RESOLVE rate with no simulated duplication

Among scenarios where no duplication was introduced, how often does GSTV incorrectly escalate to `RESOLVE`?

This is a particularly important safeguard because the project explicitly rejects the rule:

> topology discordance = paralogy

### False-RESOLVE rate in single-copy/no-duplication truth

This is the strictest version of the same safety test. A high value would indicate that discordance or reconciliation artifacts are being converted into an overly strong workflow action.

## What counts as validation

Passing the native benchmark demonstrates that the code behaves as designed under controlled structural truth. It does **not** establish sensitivity or specificity for real biological processes.

Before a stable methodological claim or software paper, the project should additionally include:

1. replicated SimPhy experiments varying ILS, D/L/T rates, taxa and gene-tree error;
2. microbial DTL simulations using an independent simulator such as Zombi;
3. sequence simulation followed by gene-tree re-estimation, so tree-estimation error enters realistically;
4. empirical benchmark datasets with independently curated orthology/paralogy or reconciliation information;
5. blinded failure-case review and explicit documentation of scenarios where GSTV cannot distinguish competing causes.

The aim is not to maximize a single accuracy number. The aim is to show where the framework is reliable, where it is conservative, and where it should hand the problem to a specialist method.
